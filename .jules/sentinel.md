## 2026-08-28 - Replace Math.random with secure random generators for IDs
**Vulnerability:** Found multiple instances where `Math.random().toString(36)` was used to generate pseudo-random IDs in security-sensitive or tracing contexts (audit logs in `p2p-mesh-core`, user/client ID generation in `apps/shelf-inventory/lib`). This provides weak entropy and could lead to predictable IDs, collisions, or forged entries.
**Learning:** Legacy PRNG-based ID generation had not been universally migrated when `generateSecureId` (SHELF-107) and `crypto.ts` UUID wrappers were introduced. Tests relying on these functions needed adjustments, specifically `fakePublicKey` length mocks in `rate-limiter.test.ts` due to side-effects of building dependencies (`edge-mesh`).
**Prevention:** Always use `crypto.randomUUID()` or `crypto.getRandomValues()` via centralized secure ID generators (`generateSecureId` / `generateUUID`). Enforce lint rules to ban `Math.random()` except in designated math/jitter modules.
