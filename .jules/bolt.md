## 2024-11-20 - [O(N) Render Optimization in Dashboard]
**Learning:** Found a codebase-specific anti-pattern in `apps/shelf-inventory/components/Dashboard.tsx` where $O(N)$ operations (`reduce`, `filter`) were defined inside closure callbacks (`getValue()`) within a `useMemo` array, but then explicitly executed inside the JSX render loop (`<StatCard value={stat.getValue()} />`). This causes the memoization to only cache the *function definitions*, not the *expensive calculations*, resulting in main-thread blocking on every re-render (e.g. toggling simple UI state like `isEditing`).
**Action:** Always pre-calculate expensive array reductions directly *inside* the `useMemo` block itself, returning primitive values (`value: number`) rather than callbacks (`getValue: () => number`). Additionally, rewrite multi-pass array iterations (`reduce`, `filter`) into single-pass `for` loops within the `useMemo` block to minimize garbage collection overhead.
